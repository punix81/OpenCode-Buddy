# Phase 3 — local plugin ↔ bridge transport (design only)

Status: **design note, nothing implemented.** Phase 3 has not started; the Product Owner will choose
the final mechanism during that phase.

## 1. Why this matters

The Phase 3 plugin runs inside the OpenCode server process and the bridge is a separate local
process. Whatever carries normalized events between them is an attack surface on a shared machine:
other local users, other processes of the same user, and containers that can reach the host network.

A loopback TCP port is **not** an authentication mechanism. Any process that can open a socket to
`127.0.0.1` can talk to it, and on Linux any process in the same network namespace can reach it.

## 2. Options

### A. Unix domain socket (Linux, macOS)

- Bind a socket inside a directory only the user can traverse, for example
  `$XDG_RUNTIME_DIR/opencode-buddy/bridge.sock` with directory mode `0700` and socket mode `0600`.
- Verify the peer identity in addition to filesystem permissions:
  - Linux: `SO_PEERCRED` gives pid, uid and gid of the connecting process.
  - macOS: `LOCAL_PEERCRED` / `getpeereid()`.
- No TCP stack involved; not reachable from another machine, and not reachable from a container unless
  the socket path is mounted into it.
- Cost: one code path per platform, plus re-creating a stale socket file after a crash.

### B. Named pipe (Windows)

- `\\.\pipe\<name>` created with an explicit security descriptor that grants access to the current
  user SID only, and with `PIPE_REJECT_REMOTE_CLIENTS`.
- Identify the client with `GetNamedPipeClientProcessId` plus the client token's SID, and check that
  the SID matches the expected user.
- No network exposure; the ACL is the authorisation.
- Cost: an SDDL string and a token check that must be written carefully; a permissive default ACL
  would silently defeat it.

### C. TCP loopback with local authentication

- Bind explicitly to `127.0.0.1` (and `::1` if used), never to `0.0.0.0`.
- Require a per-run bearer token: 256 random bits generated by the bridge at start, written to a file
  with mode `0600` (or passed in the environment to the child process), compared in constant time.
- Reject requests without the token before parsing any payload.
- Weaknesses that remain: any process able to read the token file can impersonate the plugin; a
  container with host networking can reach the port and only needs the token; the port is visible to
  local port scanners.
- Strength: works identically on every OS and needs no platform-specific API.

## 3. Comparison

| Criterion | Unix socket | Named pipe | TCP + token |
| --- | --- | --- | --- |
| Reachable from another machine | no | no | only if bound wrongly or forwarded |
| Reachable by another local user | no (0700/0600) | no (ACL) | token-dependent |
| Peer identity check | yes (uid) | yes (SID) | no, bearer secret only |
| Platform code | POSIX only | Windows only | portable |
| Failure mode when misconfigured | socket in a world-writable directory | permissive ACL | port bound to 0.0.0.0 |
| Extra secret to protect | none | none | token file |

## 4. Recommendation

- **Linux and macOS:** Unix domain socket in a `0700` directory, socket `0600`, plus a peer-credential
  check against the expected uid. Do not fall back to TCP silently.
- **Windows:** named pipe restricted to the current user SID with remote clients rejected, plus a
  client SID comparison.
- **Fallback only** where neither is available: TCP on `127.0.0.1` with a per-run 256-bit token in a
  `0600` file, constant-time comparison, and a refusal to start if it cannot bind to loopback.

## 5. Non-negotiable properties for the implementation

1. Default-deny: an unauthenticated connection is closed before any message is parsed.
2. The channel carries only the already-normalised, allowlisted fields; no prompt, response, code,
   path, tool argument or credential ever crosses it.
3. The bridge never trusts the listener's identity: it validates every message exactly as it does for
   the device.
4. Bind/creation failure is a hard error, never a silent downgrade to an open port.
5. Log the transport type and the authenticated peer, never the token.

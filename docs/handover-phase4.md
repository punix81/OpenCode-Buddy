## 2. First actions after flash approval

1. Read the full flash and record the hash before touching the device.
2. Flash application-only at `0x10000` with esptool 5.7.0 `--no-stub`; read back and compare the hash.
3. Follow `docs/phase-4-report.md` §10 exactly: handshake caps, language switch, persistence,
   gestures, auto-return, System/MCP/Tokens checks.
4. Record evidence in a new `docs/evidence/phase-4-hardware-validation.md` (photos, logs, hashes,
   frame sizes, ACK latency, defects). Do not claim a measurement that was not observed.
5. If a blocker appears, roll back to the preserved Phase 3.1 application image and report the exact
   failure. Do not improvise a new image on the device.

## 3. Known traps

- The USB port is single-owner. Stop the running bridge before opening `/dev/ttyACM0` with esptool;
  restart it LIVE afterwards.
- `npm test` runs test files in parallel. The live-source tests use fake bridge objects; any new method
  on `Bridge` (as `setOpenCodeVersion` did) must also be added to the CLI pre-bridge sink and to those
  fakes, or the IPC watchdog crashes the LIVE bridge after ~15 s. This happened once and is fixed in
  `dbe3e61`; keep it in mind for future bridge methods.
- The bridge `caps` validator now accepts 24-character capability names; the installed Phase 3.1
  firmware advertises only `config.partial`. The optional `versions.opencode` is omitted by design
  until the Phase 4 image is flashed.
- Do not change GPIOs, wiring, panel rotation, the USB architecture or the Codex Astra visual
  identity.
- `docs/design/previews/` is generated by `python3 tools/ui-preview/preview.py --sheets`; regenerate
  and review the native sheets after any layout/label change.
- Accents are composed as primitives over the pinned ASCII fonts. A new translation containing an
  unsupported character fails `test_localization.cpp`; do not bypass it with `?`.

## 4. Phase 5 pointers

- One-hour (or longer) soak of the **final** bridge and Phase 4 firmware, with MOCK stress and a live
  session; measure heap/FPS on the diagnostic build separate from release.
- Revisit only standard Phase 5 items: fuzzing, disconnect storms, coverage, dependency/licence audit,
  threat-model review, 8-hour run.
- Context utilization remains an open product question: only implement it when a verified current
  occupancy and model capacity both exist; never derive it from cumulative tokens.
- Windows named pipes and packaging remain Phase 6.
